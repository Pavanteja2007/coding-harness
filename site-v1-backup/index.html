The thesis

The integration is the point.

Layer 1 · Harness

Plan, execute, and gate on the tests.

A planner decomposes the fix into small, verifiable steps; a step agent executes them; a verifier gate decides completion. The original repo is snapshotted and never touched — you get a clean diff. Every run resumes from completed steps via a resume contract.

rationale.md

What was wrong: mean() returned the sum, not the average.

What changed: divide the accumulated sum by len(values).

Why it's correct: target test + full suite pass, no regressions.

src/mathutil.py
  def mean(values):
-     return sum(values)
+     return sum(values) / len(values)

Layer 2 · Execution

Every command runs boxed in.

Every command runs in a fresh Docker container — read-only rootfs, no network, resource limits, cap-drop ALL. Verification is stateless and flake-aware. The sandbox was adversarially confirmed: 24/24 sequential + concurrent attack suites.

Layer 3 · Runtime · the novel mechanism

Adaptive model routing, measured — not asserted.

Per call, Vex predicts difficulty — an intrinsic signal from the issue text plus a struggle signal from the conversation tail (failing tests, burned turns) — and routes easy/medium → a cheap model, hard → an expensive one. Every call lands in a per-task JSONL ledger.

Layer 4 · Memory + MCP

A code graph any agent can query.

A tree-sitter code graph (functions, classes, calls, imports) and a SQLite decision memory that auto-ingests every task's structured state. Vex exposes it over an MCP server with 5 tools — query_structure, query_decisions, record_decision, task_status, list_repos — so any MCP client (Claude Code, Cursor, …) can query it. Vex is also an MCP client.

mcp
$ vex mcp call "python -m mcp_server" query_decisions --args '{"query":"pytest"}'
→ [{ "decision": "pin dev-only deps per-repo",
     "task": "arrow#fix-parse", … }]
